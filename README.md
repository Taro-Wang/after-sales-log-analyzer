# After Sales Log Analyzer

**版本：** v8.7  
**作者：** Taro Wang (道工 DaoGong)  
**用途：** DIDA 售后运营团队专用的订单日志判读工具

## 功能描述

本 Skill 用于分析酒店预订订单的操作日志，输出标准化的争议判定结果：**【渠反馈】【供反馈】各一句话总结（置顶）+ 一张两列多行（竖排）表**，帮助售后运营团队快速判断争议内容、责任方与金额来源。

**身份定位：DIDA 售后运营专家**

- **供应商侧**：尽可能从供应商处收到赔付或少付钱
- **渠道侧**：从渠道处多收钱或减少赔付
- **底线原则**：不准编造任何信息，不准预设任何可能，严格根据日志事实作出判断

## 核心能力

- ✅ 双订单号匹配与提取（`bookingNumberType=2` → 渠道订单号；`=3` → 供应商订单号）
- ✅ 争议内容 7 项枚举判定（间夜/餐型/房型/床型/人数/被动无房/主动取消）
- ✅ 争议责任方二值判定（供责/渠责）
- ✅ **口径隔离红线**：【供反馈】只基于供应商沟通日志、【渠反馈】只基于渠道沟通日志，单方之词必须写"称…"，严禁提升为对方认可或"双方一致、赔付成立"（防资损）
- ✅ **争议金额严格溯源**：只记录人工对话日志中的金额，照抄原文完整币种链（含等式关系，如 `58000韩元=287.30人民币=42.77美金`），禁取系统改单金额与取消罚金字段；对话无金额时供责填"供应商责任需要赔付"、渠责填"渠道取消需要付罚金"
- ✅ 智能识别人工沟通记录（排除系统日志、内部改单操作）

## 使用方式

### 在 OpenClaw 中调用

```
请基于 URL 中的内容执行 after-sales-log-analyzer skill：http://tiger-api.didaadmin.com/api/v2/BookingManage/GetBookingOperationLogByToken?token=[TOKEN]
```

> 该接口会 302 跳转至 https；若返回「token 无效或已过期」，直接粘贴日志 JSON 内容即可分析。

### 输出示例（v8.7）

```markdown
【渠反馈】渠道称客人两日在酒店前台各现付第三人早餐费共 58000 韩元（1 人 × 2 天），并称已向酒店核实情况属实。

【供反馈】供应商未认责、未作任何承诺。

| 字段 | 内容 |
|------|------|
| **订单号** | 1805318328 / 2075751407641821184 |
| **渠道ID** | QUNAR_QX |
| **供应商ID** | 26（Agoda） |
| **争议内容** | 餐型 |
| **争议责任方** | 供责 |
| **争议金额** | 58000韩元=287.30人民币=42.77美金 |
| **争议金额来源** | 客人自费 |
```

## 字段说明

| 字段 | 说明 |
|------|------|
| 订单号 | 渠道订单号 / 供应商订单号（按 bookingNumberType 规则取最新日志） |
| 渠道ID | clientID |
| 供应商ID | supplierID（有 supplierName 时附带） |
| 争议内容 | 7 项枚举：间夜 / 餐型 / 房型 / 床型 / 人数 / 被动无房 / 主动取消（可多选） |
| 争议责任方 | 供责（订单未按原安排执行或到店无房）/ 渠责（客人主动取消） |
| 争议金额 | 人工对话日志中的原文完整金额链；对话无金额时供责填"供应商责任需要赔付"、渠责填"渠道取消需要付罚金" |
| 争议金额来源 | 客人自费 / 渠道付费 / 供应商补偿 / 其他 |
| 【渠反馈】 | 一句话总结渠道最终立场（置顶输出；仅基于渠道沟通日志；"称…"vs"确认/承诺…"严格区分） |
| 【供反馈】 | 一句话总结供应商最终立场（仅基于供应商沟通日志；未表态须如实写"未表态/未认责/未达成共识"） |

## 输出纪律

- 严格限定为【渠反馈】【供反馈】各一句话（置顶）+ 一张两列表，不附加任何建议、备注、时间线或思考过程
- 口径隔离是资损防线：供应商的话只进供反馈、渠道的话只进渠反馈，绝不互移；酒店 ≠ 供应商、酒店 ≠ 渠道，经谁转述算谁的一面之词
- 争议金额必须可追溯：读到金额即可在【供反馈】或【渠反馈】中看到金额来源对应

## 版本历史

- **v8.7** (2026-09-04): 输出顺序与金额口径调整
  - 【渠反馈】置顶、【供反馈】其次、表格最后
  - 争议金额只记人工对话日志中的金额，禁记系统改单金额（`修改供应商应赔道旅金额:=>X` 等）与取消罚金字段
  - 对话无金额时供责固定填"供应商责任需要赔付"、渠责固定填"渠道取消需要付罚金"，不填其他推断文字
- **v8.6** (2026-09-04): 争议金额保留原文完整币种链（如"58000韩元=287.30人民币=42.77美金"原样照抄，不截断不换算）；新增可追溯要求
- **v8.5** (2026-09-04): 两段反馈各精简为一句话，禁止时间线/逐条罗列/啰嗦展开
- **v8.4** (2026-09-04): 口径隔离强制红线——供反馈只基于供应商沟通日志、渠反馈只基于渠道沟通日志；单方转述"已与酒店/对方核实"仅为单方之词，须写"称…"，严禁提升为对方认可或"双方一致、赔付成立"
